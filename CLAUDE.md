# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Astro 6 + Vue 3 + MDX public site. See `../CLAUDE.md` for the cross-repo picture (shared types, branch flow). The README is still the unmodified Astro starter template — don't trust it.

## Commands

- `pnpm dev` / `pnpm build` / `pnpm preview` — standard Astro; `predev` runs `sync-types` (needs network)
- `pnpm lint` — eslint; `pnpm format` — prettier
- Stylelint has **no script**: run `pnpm exec stylelint <files>`
- No tests exist.

## Gotchas

- `src/types/` is generated by `pnpm sync-types` — never hand-edit.
- `.env.local` (`PUBLIC_API_URL=http://localhost:3333`) and `.env.prod` are **committed on purpose**; only `PUBLIC_API_URL` exists as env config.
- `@use-compose/ui` (currently `0.10.2`) needs `ssr.noExternal` + `optimizeDeps.include` workarounds in the Astro/Vite config, and a single shared Vue via the `pnpm-workspace.yaml` catalog/override — two copies of Vue in one render break `renderSlot`. Don't bump without checking both still apply.
- Deploy: `ci.yml` is canonical (lint → build → rsync `dist/` on push to `main`). `deploy.yml` is leftover and broken (rsyncs `./website-build/` which doesn't exist) — ignore it.
- `@use-compose/ui`/Vue composition lives in `src/components/vue/`, split by role — `views/` (page roots, e.g. `HomeView.vue`, hydrated from `index.astro` with a single `client:load`), `ui/` (reusable pieces like `SiteHeader.vue`), `layout/` (CUBE-style shells like `Cover.vue`). Domain-specific Vue components (`ProjectCard.vue`, `ProjectGrid.vue`) live in `src/projects/components/` alongside the existing domain-type boundary there, not under `components/vue/`. Compose framework components _inside_ a `.vue` file via normal `<script setup>` imports — never as nested `client:*`-tagged children inside another framework component's `.astro`-authored slot. Astro's islands model gives every top-level framework component reference in an `.astro` template its own independent hydration root, even when nested in another's slot, so that pattern silently creates disconnected Vue app instances that don't share `AppCompose`'s theme context (this bit the old `Card.astro`/`SiteWrapper.astro` setup, since replaced). `HomeView.vue` → `SiteShell.vue` is the reference pattern.
- No `vue-router` yet. When a section needs real nested sub-routes (e.g. a future `/projects/web` vs `/projects/mobile`), follow [`florivdg/astro-vue-router`](https://github.com/florivdg/astro-vue-router): one Astro page per concrete path via `getStaticPaths`, each hydrating the same Vue root, with `vue-router` (web history mode) taking over client-side navigation between them post-hydration. No SSR adapter needed — stays compatible with the static rsync deploy.
